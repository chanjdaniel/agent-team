## Deliver through no-mistakes

1. Bring the branch up to date with the base: `git fetch origin`; if `git merge-base --is-ancestor origin/{{base}} HEAD` fails, merge `origin/{{base}}` with a merge commit (`git merge origin/{{base}}`, never a rebase), resolve any conflict and re-run what the conflicts touched.
   A conflict whose resolution is a judgment call on behaviour goes to `coordinator` as `{{task}} QUESTION <the conflict> | options: ...`.
2. Find what your branch made false: for each file, command, flag, setting and path it adds, renames or removes (`git diff --stat origin/{{base}}...HEAD`), `git grep` its name in the repository's Markdown, `CLAUDE.md`, `AGENTS.md` and script headers, and fix every line that no longer holds, in the same PR.
3. Push the branch (under a Disclosure section, not before the review passes: the reviewer reads your local head) and send `{{task}} DONE review-ready <the full sha of HEAD>` to `coordinator`, then wait: the team reviews that head before the gate runs, so the gate runs once.
   Fix each finding the coordinator sends you on the branch and push; once they are fixed, or the coordinator says the review passed, go on.
4. Run `/no-mistakes` with the gate's ci step skipped for the run (`no-mistakes axi run --skip ci --intent "<the intent>"`), so the run ends with outcome `passed` once its pr step has opened or updated the PR, and CI is the coordinator's wait, as step 7 says; never wait for `checks-passed`, and never abort a run to end it.
   Give it an intent that says what this PR changes, in words a reader of the repository can follow, with no task, ticket, phase or retro number (the task's goal is "{{goal}}": on a phase, this phase's part of it alone), under a Disclosure section put in its terms, since the gate drafts the PR's title and body from it.
   A step that parks with no finding you approve yourself, with no QUESTION, only when the park is one of these kinds, named by its id:
   - `review-coverage`: the review step parks on "review coverage is incomplete" alone, and the team review read every file it names at a head this branch contains: a head you or the builder before you sent as `DONE review-ready`, or one the coordinator names as reviewed, that `git merge-base --is-ancestor <that head> HEAD` passes for and whose `git diff --name-only origin/{{base}}...<that head>` lists the file.
   {{> gate-parks}}
   Approve it with `no-mistakes axi respond --action approve`, write a build note in `{{task_dir}}/build-notes/` naming the run, the step, the park's id and what the gate said, and put the ids of the parks the run approved in its `DONE gate` line as `approved=<ids, comma-separated>`.
   Any other park, and a finding at any step, goes to `coordinator` as a QUESTION.
5. The PR must target `{{base}}`; if the gate opens it against another branch, retarget it to `{{base}}` and close any duplicate.
6. When the gate's run ends `passed`, repeat step 1; if it merged anything, push, noting each file that conflicted.
   The gate runs again only for a commit of yours that changes behaviour, such as the fix to a red check, and never for a merge of the base, however its conflicts were resolved (clean, in docs alone or in code), or for a commit that changes only docs, comments or the PR body: those are re-reviewed and checked by CI.
   Then read the PR's title and body, which the gate drafted from your intent, with `gh pr view <full url> --json title,body`, as Daniel will on GitHub and the review will: a title that is a Conventional Commit; a body that opens with what this PR changes, in words a reader of the repository can follow, with no task, ticket, phase or retro number, true to the change at the head the run pushed, with no internal name a reader cannot follow and no value but a fixture's, and under a Disclosure section in its terms; fix each that falls short on the PR with `gh pr edit <full url> --title <title>` or `gh pr edit <full url> --body-file <file>` before you send `PR`: an edit of the PR is no commit, so it runs no gate.
7. Send `{{task}} PR <full url>` to `coordinator`, followed by `merged {{base}} conflicts: <each file that conflicted, or none>` when step 6 merged, and stop: the delivery ends there, with no wait on the PR's GitHub checks, since the coordinator's script waits on them once the review passes, and a red check comes back to you from the coordinator as a fix round, as a review's findings do.
   The gate leaves Playwright to CI, so `e2e` runs with the PR's other checks, which the coordinator's wait reads like any other.

At each gate run's end (it pushed, went red, or was aborted), send `{{task}} DONE gate run=<its id> head=<the full sha it ran on> outcome=<pushed|red|aborted> minutes=<each step's minutes from no-mistakes axi status --run <its id>, as one JSON object>` to `coordinator`, a run whose gate outcome is `passed` reported as `outcome=pushed`, with `cause=<review|notes|gate-finding|load|tooling|base-merge|other>` when the run repeats an earlier one on the same PR, and `approved=<ids>` when you approved a park of it yourself, as step 4 says.

Never run a command that needs `sudo`; send `{{task}} BLOCKED <the command> needs sudo` to `coordinator` instead.
