Start the wait for the PR's GitHub checks with `{{team_bin}}/team-ci-wait {{pr}} {{head}}`, run with Bash `run_in_background`, before you read anything, so the run and your reading overlap; every check must pass before you pass the PR, so a pass delivers only once the wait has ended.
A review that sends any finding back delivers as soon as `{{task_dir}}/review.md` is written, without waiting for the end: its CI section names the checks still running, the builder fixes a failed check on its own wait, and the rereview of its next head waits for that head's checks; a wait that ends after you delivered needs nothing more from you.
Act on how the wait ended: exit 0, every check passed or the head has none; exit 1, each failed check it names is a `blocking` finding; on a head other than `{{head}}`, read the runs of `{{head}}` itself with `gh run list --repo {{repo}} --commit {{head}}`, since the builder pushes its fix of a failed check at once: each failed run is a `blocking` finding, and only when none failed does the moved head, as a stuck check does, go to `coordinator` as `{{task}} BLOCKED <its message>`; exit 75, run it again, or report as its message says.
When a check failed, the PR has usually moved past `{{head}}` by the time you deliver, and `team-review-status` refuses your head: post your comment as usual, set no status, and send your `DONE findings` with each failed check counted as `blocking`, which the coordinator takes on a moved head; that move is no `BLOCKED`.
